凭据全生命周期全流程

三类凭据按「持有方 / 签发方」分界的完整生命周期：网关托管、用户代填、平台签发；以及轮换、吊销与过期三种终态的处置差异。

依据 网关凭据托管 / 用户代填账号托管 / 签发凭据管理对应页面 三页均涉及三类凭据不可混用
← 返回原型索引

平台里的凭据按「谁持有、谁签发」分成三类，分属三个页面、三条流程。混用会造成职责不清 —— 三类凭据的存储与落库口径不同，这是本流程要划清的边界。

1 三类凭据的分界

类别持有方签发方对应页面是否落库典型用途
网关托管凭据网关外部系统网关凭据托管加密落库网关 → 上游系统的连接级凭据（Basic / API-Key / OAuth2 Client / mTLS 证书）
用户代填账号平台代用户持有用户 / 管理员录入用户代填账号托管加密落库资产账号密码代填；用户在资产页看到的仍是自己的账号
平台签发凭据访问主体平台签发凭据管理仅存元数据与公钥客户端 License 证书、智能体短时凭据
区分要点：网关托管与用户代填都是「代为保管」；平台签发是「平台自己发的」，平台只留公钥与元数据，不保存可用于冒用的私钥。

2 主线一 · 网关托管凭据

新增托管凭据绑定上游资产选凭据类型录入并加密落库启用网关取用
1
新增托管凭据安全管理员

填写凭据名称与类型（Basic / API-Key / OAuth2 Client / mTLS）。

2
绑定上游资产安全管理员

指定该凭据服务于哪个上游系统。一个上游可挂多份，但同一时刻只有一份处于生效态。

3
录入凭据内容安全管理员

口令 / Key / Secret 加密落库；mTLS 走证书上传。⚠ 明文不出执行组件 —— 日志、审计、链路、数据库均不得出现明文。

4
启用安全管理员

置为已启用后，网关在访问该上游时按此凭据出站。

5
网关取用网关

发起上游请求时装载凭据。解密仅在执行组件内存进行，用毕即销毁。

分支与失败
凭据内容校验失败（格式 / 长度 / 证书链）拒绝保存，不入库
上游系统不可达连通性测试失败；凭据仍可保存但不建议启用
凭据轮换支持平滑轮换：新旧并存至旧凭据失效，切换过程不中断业务
主密钥轮换平台侧支持主密钥轮换，过程对业务透明
删除仍被上游引用的凭据拒绝；须先解除上游引用或改绑其它凭据

3 主线二 · 用户代填账号

选定资产资产侧配登录契约选托管模式录入账号登录时代填解密仅在执行组件
配置面分两处、各管一段：登录契约（登录页地址、字段选择器、登录形态）是资产属性，同一资产下所有用户共用一份，配在「资产详情 → 身份适配」页签的 D 档（账号密码代填）；凭据本体（谁在哪个资产用什么账号密码）才是「用户代填账号托管」的职责。平台不假设统一登录页；未配置契约的资产不执行代填，直接回退手动登录。
1
选定资产用户 / 管理员

代填按资产建立，不是按用户。先在资产列表选定目标应用。

2
资产侧配登录契约管理员

在「资产详情 → 身份适配」页签选 D 档，为该资产配 登录页地址、登录形态（单步 / 两步 / 多步）、账号字段选择器、密码字段选择器、提交按钮选择器、提交方式（自动提交 / 等用户点击）与验证码策略。契约随资产走，不写在用户账号上。

3
契约测试管理员

按契约执行一次模拟填充，验证选择器命中；选择器失效即视为契约失效，须重新配置并测试通过方可恢复代填。

4
选托管模式用户 / 管理员

在「用户代填账号托管」录入时选用户自管或管理员托管 —— 用户自管：用户自己录账号，管理员不可见；管理员托管：以组织资产名义录入（如共享的服务账号）。

5
录入账号用户 / 管理员

录入凭据本体：被访问应用 + 账号 + 口令。账号可明文展示（便于核对），口令一律加密落库。该资产的契约若已配好则直接引用，未配则标记待配契约。

6
登录时代填网关 / SDK

访问该资产时，按该资产的契约填充账号口令 → 按提交方式提交 → 校验登录结果。无端＝网关执行；有端＝SDK 执行。

7
解密与销毁执行组件

有端 SDK 不保存任何凭据（含加密态），每次代填实时向服务端请求，内存解密、用毕即销毁。

分支与失败
代填失败（页面结构不匹配 / 选择器失效）标记「代填失败」并记录；管理员重配契约、测试通过后恢复
资产登录页改版原选择器全部失效 → 停止代填，回退手动登录，待重配契约
两步登录（账号页 → 密码页）两个页面各配一组选择器；第二步未命中则整体失败
验证码（图形 / 短信）不承诺全免密；识别失败即转人工输入
用户在资产侧自行改了口令以用户最新录入口径为准；不自管模式下管理员不可见
执行组件完整性校验未通过不提供代填（执行组件必须可信）
日志或审计中出现明文凭据红线违规；该组件禁止参与代填

4 主线三 · 平台签发凭据

发起签发选定持有主体选类型生成凭据有效期管理轮换 / 吊销
1
发起签发安全管理员

为访问主体签发凭据。签约对象是主体，不是连接。

2
选定持有主体安全管理员

客户端实例（License 证书）或智能体实例（短时凭据）。身份模块引用本模块的凭据记录，本模块不反向引用身份模块。

3
生成凭据平台

客户端 License 证书：自定义封装 License 容器，内封授权信息（客户端序列号 / 终端序列号 / 授权范围 / 有效期）与建立 TLCP 隧道所需的 CA 证书链（只含公钥）；容器内含该终端的设备序列号。智能体短时凭据：由服务端为本机智能体进程颁发，短时效。

4
有效期管理平台

到期前提醒；轮换过渡期下同一实例可挂多份证书（新旧共存），支持并存上限设置。

5
轮换 / 吊销安全管理员

轮换：签发新凭据、旧的保留至到期。吊销：立即失效，持有主体须重新签发。支持批量吊销（勾选多行一次处置）。

分支与失败
持有主体不存在或已注销拒绝签发
证书即将过期状态置「即将过期」并提醒；可批量轮换
吊销已吊销的凭据幂等；不重复入审计
批量吊销含已失效项有效项照常吊销，失效项跳过；结果逐项回报
轮换时并存数超上限拒绝新增，须先清理旧证书

5 三种终态的处置差异

终态触发方式凭据本体持有主体影响可否恢复
过期到达有效期保留（仅失效）需重新签发否（须重新签发）
吊销管理员显式操作立即失效立刻失去能力否（须重新签发）
轮换管理员发起新旧并存至旧者到期业务不中断—（属过渡态，非终态）
安全红线：① 明文凭据不出执行组件；② 有端 SDK 不保存凭据，代填时实时请求、用毕即销毁；③ 执行组件必须可信，未通过完整性校验的 SDK 不提供代填。
依据：网关凭据托管页 / 用户代填账号托管页 / 签发凭据管理页；身份模块（客户端实例管理 / 智能体软件 / 实例管理）引用签发凭据　三类凭据存储口径不同，不可混用

6 凭据三列语义与存储口径

  • 「持有主体」「绑定主体标识」「授权范围」三列各答一问：
    · 持有主体＝业务台账里的可读名称（客户端实例＝软件 @ 终端；智能体实例＝软件 @ 终端（进程 N），PID 是「哪个进程」的唯一判别符），会随命名调整而变，同一终端上的同名软件并不唯一；
    · 绑定主体标识＝凭据内部真正绑定的主体标识（客户端实例取其实例序列号，智能体短时凭据取其宿主客户端实例序列号）—— 网关校验与按主体追溯比对的正是它；
    · 授权范围＝这份凭据被允许访问的对象集合：证书类通常是资产集合，短时凭据则通常收敛到具体资产 / 资源（如经无端网关访问某个具体资产的浏览器所持的短时凭据，其授权范围就是那一个资产）。短时凭据同样有授权范围。
  • 网关托管凭据（口令 / 密钥类）：明文不可回读，凭据值录入后仅以掩码呈现、变更一律走「轮换（替换）」；被资产引用时不可删除。「应用（绑定）」只发生在资产侧 —— 哪个资产用哪条凭据在资产「身份适配 → 机器身份」中配置，本页只做反向只读反映。
  • 信任锚（根 CA）只托管公钥证书（信任锚 / 自签证书，不含私钥）；mTLS 客户端证书含私钥，私钥不出平台、不可导出、不可回读，界面仅呈现证书主体、颁发者、有效期与指纹。轮换＝就地更新（同一台账记录，不新增条目）；若上游切换期间需新旧并存，先「另存为新的一条」，切换完成后再删除旧条。
  • 用户代填托管模式的告知-同意：用户自管＝用户本人录入，可随时查看、删除自己名下凭据（撤销授权）；管理员托管＝组织资产，管理员统一录入维护，用户无感、无权删除。⚠ 首次录入的确认动作即构成用户对代填账号托管的授权（告知-同意）；删除后停止代填、需重新录入才恢复，删除动作全量审计。
  • 存储口径按凭据类别分档：「加密落库」只适用于代填类凭据（资产账号密码）；注入类身份材料（token / key）不落库 —— 有端 SDK 一律不保存、用时实时向服务端请求。凭据值以国密 SM4 加密落库，密钥经内置轻量 KMS 两级架构（主密钥 + DEK）管理；解密仅在执行代填的组件内存进行（无端＝网关、有端＝SDK）。
