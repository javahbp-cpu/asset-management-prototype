强认证器绑定与重置全流程

强认证器从登记到重置的全过程：登记须由已认证会话发起、challenge 一次性消费、吊销按凭据 ID 执行、全不可用时的管理员重置通道。

依据 强认证器绑定管理对应页面 强认证器绑定管理登记须已认证会话
← 返回原型索引

强认证器（设备生物因素 / 活体人脸 / USB Key / passkey）是 L4~L5 高强度认证的载体。它的登记、吊销与重置都带身份核验前置要求，这是它与普通凭据最大的不同。

1 主干步骤 · 登记

已认证会话发起取一次性 challenge本机完成核验提交公钥与凭据绑定到用户置为有效
登记必须由已认证会话发起 —— 禁止匿名登记。这是防止攻击者抢先为他人登记认证器的关键前置。
1
已认证会话发起用户

用户已在平台完成一次有效认证，登记动作在该会话内发起。未经认证的请求直接拒绝，不进入后续任何环节。

2
取一次性 challenge平台 → 客户端

平台下发 challenge。⚠ challenge 一次性消费：无论后续成功或失败，立即作废，不可复用。

3
本机完成核验用户 + 认证器

在终端本机完成生物核验 / 人脸活体 / USB Key 触碰。生物特征不出本机，平台侧只收到签名结果。

4
提交公钥与凭据客户端 → 平台

提交认证器公钥、凭据类型（绑定型 / 可同步凭据）、RP ID 与登记设备标识。

5
绑定到用户平台

把该认证器绑定到发起会话的该用户。绑定关系是一对多（一个用户可多枚）。

6
置为有效平台

记录安全级别（L4 / L5）、凭据类型、登记时间与登记设备，状态置有效。

2 主干步骤 · 吊销与重置

管理员吊销按凭据 ID 执行置为已吊销或管理员重置核验身份吊销该用户全部凭据
1
管理员吊销（单枚）安全管理员

吊销指定的一枚认证器。吊销后立即失效，用户须重新登记。

2
按凭据 ID 执行平台

⚠ 若为可同步凭据（如 passkey），按凭据 ID 单独执行、不依赖设备状态 —— 不能因为「设备还在」就认为凭据仍可用。

3
管理员重置（全部）安全管理员

当某用户全部认证器均不可用时走此通道：经身份核验后，吊销该用户全部 WebAuthn 凭据并允许重新登记。

4
重置全程入审计平台

重置是高风险动作：核验方式、操作人、目标用户、处置结果全部记审计。

分支与失败
未经认证的会话发起登记拒绝；不生成 challenge
challenge 已消费 / 过期 / 不匹配拒绝；challenge 不可复用
本机核验失败登记失败；无凭据写入
重复登记同一凭据幂等识别并拒绝（同一凭据 ID 不得绑两次）
可同步凭据在多设备出现按凭据 ID 统一管理；吊销一次即全端失效
用户仍有其它可用认证器管理员重置不应被使用；优先走单枚吊销

3 认证器属性与约束

属性取值说明
认证器类型设备生物因素（指纹）/ 活体人脸 / USB Key / passkey决定核验方式与可携带性
凭据类型绑定型 / 可同步凭据可同步凭据会跨设备存在，吊销须按凭据 ID 执行
安全级别L4 / L5仅 L4 / L5 可置位抗钓鱼；抗钓鱼是方式的内生属性
RP ID如 baize.example.com绑定域名；更换域名须重新登记
登记设备终端标识用于审计溯源，不作为吊销的唯一依据
「认证方式字典」中的 L4 / L5 方式，其实际可用性取决于用户是否已完成认证器登记 —— 字典回答「有哪些方式」，本页回答「这个用户此刻能否用」。
依据：强认证器绑定管理页（登记 / 吊销 / 重置）；认证方式字典页（L4~L5 与抗钓鱼属性）　登记须已认证会话；challenge 一次性

4 登记前置与作用域约束

  • 登记前置与安全约束：① 必须由已认证会话发起（禁止匿名登记）；② challenge 一次性（平台生成、一次性消费、与注册记录绑定，随机位数 ≥128 bit，未消费记录 TTL ≤5 分钟）；③ fail-closed（策略要求 L4 及以上而认证器不可用或未注册时，结果为拒绝，不静默回退）；④ 错误响应不暴露内部信息（不暴露认证器型号、凭据 ID）；⑤ RP ID 校验（认证器因 RP ID 不符拒绝签名，平台不产生认证记录；资产外部域不参与 RP ID 判定）。
  • RP ID 是认证器凭据的作用域（不属于绑定项）：取发起认证 origin 的可注册域名（eTLD+1），须为 origin 的域名后缀且非公共后缀；同一 RP ID 下的子域共享凭据集合，不得跨 eTLD 混用；平台主域变更须按新 RP ID 重新登记。
  • 绑定项三项：用户 / 安全级别 / 凭据绑定属性（默认按绑定型登记）。启用可同步凭据（passkey）时须标注其可漫游属性，吊销按凭据 ID 单独执行并即时失效，不依赖设备状态。「凭据绑定属性」列描述的是凭据自身可否随账号漫游，与「认证方式」（凭据的种类：指纹 / USB Key / 活体人脸…）不是同一维度。
  • 多枚冗余与恢复：同一用户可登记多枚认证器（同级别多枚、跨级别多枚），天然构成冗余 —— 单枚不可用不影响其余凭据继续认证；只有全部不可用时才走身份核验后的管理员重置（吊销该用户全部认证器凭据并允许重新登记，全程记审计）。
